The Malaysian e-invoicing mandate

Phased by turnover

LHDN began with the largest companies in 2024 and is extending the mandate to smaller annual-turnover bands through 2025–2026, each with a grace period.

MyInvois by default

Invoices are cleared through the MyInvois system (API or portal) as UBL 2.1 in XML or JSON, with a digital signature, and a validated QR.

The gap

Many SMEs still invoice from Excel or older software that can't produce a MyInvois document. Mapping the data to a file that validates is where it stalls.

Based on the LHDN e-Invoice Guidelines and the MyInvois SDK (sdk.myinvois.hasil.gov.my). Always confirm your situation and timeline with your tax agent and LHDN.

Validated against the official SDK rules

Every file is checked against the rules published in the MyInvois SDK before it leaves your hands — the same checks MyInvois runs on submission:

✓ 0 errors

Standard B2B invoice generated from Excel, as a MyInvois UBL 2.1 document in both XML and JSON, from one source — so the two always match.

✓ 0 errors

Mandatory fields, code lists (classification, tax type, state, MSIC, UN/ECE units) and the OTH tax scheme, plus the official UBL 2.1 schema.

✓ 0 errors

Service Tax at 8% on three lines plus a "Not Applicable" disbursement line — tax subtotals grouped and totals recomputed correctly.

Broken data is caught before it reaches MyInvois: an invoice with no supplier TIN, an invalid classification code or a wrong total is rejected with the exact rule it breaks.
